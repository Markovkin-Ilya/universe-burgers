# Universe Burgers

Одностраничное приложение для заказа бургеров. Пользователь собирает бургер из ингредиентов в конструкторе, оформляет заказ, следит за лентой заказов и управляет профилем.

Проект выполнен в рамках учебного курса Практикума. Макет и UI-компоненты предоставлены в шаблоне, а логика состояния, маршрутизация, авторизация, работа с API и тесты написаны мной.

Деплоя пока нет, приложение запускается локально.

## Стек

- React 18, TypeScript
- Redux Toolkit (`configureStore`, `combineSlices`, `createAsyncThunk`), React Redux 9
- React Router 6
- Webpack 5, ts-loader, dotenv-webpack
- Jest и ts-jest для unit-тестов, Cypress для e2e-тестов
- Storybook 7, ESLint, Prettier

## Установка и запуск

1. Установите зависимости:

   ```
   npm install
   ```

2. Создайте файл `.env` в корне проекта на основе `.env.example`. Переменная `BURGER_API_URL` задает адрес API, без нее запросы к серверу не работают:

   ```
   BURGER_API_URL=https://norma.education-services.ru/api
   ```

3. Запустите dev-сервер:

   ```
   npm start
   ```

   Приложение откроется на `http://localhost:4000`.

Дополнительные команды:

| Команда | Описание |
| --- | --- |
| `npm test` | Unit-тесты Jest с отчетом о покрытии (папка `coverage/`) |
| `npm run cypress:open` | Запуск Cypress e2e-тестов. Сначала запустите dev-сервер, так как тесты открывают `http://localhost:4000` |
| `npm run lint` | Проверка ESLint |
| `npm run format` | Форматирование Prettier |
| `npm run storybook` | Storybook на `http://localhost:6006` |

## Структура проекта

```
src/
├── components/        # UI-компоненты (шаблон) и обертки с логикой
│   ├── app/           # корневой компонент: роутинг и модальные окна
│   ├── ui/            # презентационные компоненты и страницы из шаблона
│   └── protected.tsx  # защищенные маршруты
├── pages/             # страницы: constructor, feed, login, register, profile и др.
├── services/          # Redux-слайсы и thunk-действия
│   ├── constructor/   # выбранная булка и начинка, порядок ингредиентов
│   ├── feed/          # лента заказов всех пользователей
│   ├── ingredients/   # список ингредиентов
│   ├── order/         # оформление заказа
│   ├── profile-orders/# заказы текущего пользователя
│   ├── user/          # авторизация, профиль, флаг проверки авторизации
│   └── store.ts       # сборка глобального store
├── utils/
│   ├── burger-api.ts  # запросы к API и обновление токенов
│   ├── cookie.ts      # работа с cookie
│   └── types.ts       # типы данных
cypress/
└── e2e/               # e2e-тесты
```

Модули импортируются через алиасы `@pages`, `@components`, `@ui`, `@ui-pages`, `@utils-types`, `@api`.

## Моя зона ответственности

Я отвечал за логику приложения:

- **Redux-слайсы и thunk-действия** для ингредиентов, конструктора, заказа, ленты, заказов профиля и пользователя.
- **Роутинг**: маршруты в `src/components/app/app.tsx`, модальные окна для деталей ингредиента и заказа через `location.state.background`.
- **Авторизация**: защищенные маршруты (`Protected`), разделение страниц для гостей и авторизованных пользователей, проверка сессии при запуске приложения.
- **Работа с API**: функции в `utils/burger-api.ts`, обновление `accessToken` через `refreshToken` при ошибке `jwt expired`, хранение токенов в cookie и `localStorage`.
- **Тесты**: unit-тесты слайсов на Jest и e2e-сценарий конструктора на Cypress.

Компоненты из шаблона я использовал как есть или дорабатывал под логику store и маршрутов.
